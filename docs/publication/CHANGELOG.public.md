# 更新日志

这份文件记录 JustSaid 每个版本给使用者带来的变化,最新版本在最上面。

## [1.0.0] - 2026-09-10

第一个对外发布的版本。0.9.1 与 0.9.2 未曾对外发布,它们的内容都包含在本版本里。

### 新增
- **实时转写有了统一的三种状态**:收起时底部只保留一行最新原文的预览;点预览条、顶栏或
  左侧「转写」都能展开为覆盖下方的快速面板,并停在最新一句;点「置顶」后转写改占左侧
  整理区,右侧「替你记」与「补充记录」照常可用。往上翻看旧内容时,新转写不再把页面拉回
  底部,需要时点「回到最新」恢复跟随;从整理区的「来自」可以跳到对应原文,从「章节」回到
  某个话题时转写会收起、整理区滚到该话题。

### 修复
- **麦克风采集跟随所选输入**:录音中切换系统麦克风、或设置里选定的麦克风暂时不在时,
  采集会切到实际可用的输入并说明原因,设备回来后自动切回,不再停留在旧输入上。
- **停止自动重试后,恢复收音也能被识别;中断记录随会议保存**:采集中断用尽自动重试次数后,
  App 仍继续观察录音状态,随后重新正常收音会显示「已恢复」;自动重试结束后的中断会记录是
  哪一路声音、从何时开始、后来是否恢复,结束会议后重新打开会议库仍能看到,恢复后已发生的
  中断记录也保留。
- **采集出错后能真正恢复**:采集报错后仍在送出静音的情况,不再被当作「还在收音」而错过
  恢复;只有重新收到正常声音才会显示已恢复。
- **停止录音不再被另一路采集卡住**:麦克风与系统声音两路采集在停止时各自收尾、互不等待,
  收尾按实际两路结果保存。
- **会中总结的长请求不再被整段超时打断**:会中总结只要还在持续返回内容,就可以超过
  300 秒正常完成;超时只在长时间没有新内容时才触发。
- **删除会议后列表位置不再跳动**:删除中间某场会议后,上方的会议保持原位,下一场补位并
  被选中。

### 文档
- 随包教程补全了豆包录音文件识别与 Cloudflare R2 的申请步骤、保存顺序与验证方法。

## [0.9.2] - 2026-09-08

### 修复
- **停止自动重试后,恢复收音也能被识别**:麦克风或系统播放声音的采集在中断后用尽自动重试
  次数时,App 会继续观察录音状态。随后重新正常收音时,会显示「已恢复」,不会一直停在
  「已停止重试」。
- **中断记录会随会议保存**:自动重试结束后仍未恢复的中断,会记录是哪一路声音、从什么时候
  开始,以及后来是否恢复。结束会议后重新打开会议库,仍能看到未恢复的中断或已恢复的中断
  时间段;恢复收音后,已经发生的中断记录也会保留。
- **收尾提示会一并说明保存失败和录音中断**:单路录音保存失败、同时有录音中断时,提示会列出
  缺失的声音和中断情况,纪要按实际录到的内容生成。

## [0.9.1] - 2026-09-05

### 修复
- **录音中断的会议按实际录到的时长展示**:采集在会中断掉时,会议库以前显示的是从开始到
  结束的整段跨度,和实际录到的长度差得很远(实际录到不到一小时的一场会显示成 9 小时)。
  现在这类会议在列表里标「录到」并给出实际录到的时长;导出的会议包文件头也用
  同一个口径,不再和会议库各说一套。
- **忘记停止录音之后,会议不再空转**:采集断掉以后,App 以前会带着一场停不下来的会议继续
  跑几个小时,横幅一直停在「第 1 次自动重建」。现在自动重建是有界的:超时之后进入放弃态,
  不再无限重试;会中总结在一段时间没有新转写内容时暂停,并提示「录音已中断」,新的转写
  一进来就自动恢复。
- **上一场会议刚结束就开始新会议,不再静默失败**:上一场还在收尾时点「开始会议」,以前那次
  开始请求会被悄悄丢掉,主窗口虽然照常弹到前台、显示禁用的「正在保存…」,却没有任何提示
  说明这次点击没有生效。现在这次点击在收尾阶段就被明确拒绝,主窗口照常弹到前台并保留
  「正在保存…」这句回执,等收尾结束再开就行。
- **失败提示说明原因和下一步**:会后处理、纪要与完整度的提示不再只说「失败」,而是写清失败的
  是什么、已知的原因,以及可以做的下一步动作。
- **完整转写可以跨页拖选,右键能批量标记闲聊**:选段拖到当前可见范围之外时,焦点不再跳到
  最后一行;在已经选中的多行上右键,「标记闲聊」会对整个选区生效,和底部的批量按钮一致。

## [0.9.0] - 2026-09-04

### 新增
- **模型不再随 App 分发**:安装包不再内置离线模型。第一次打开时,若本机还没有校验通过的
  Qwen3-ASR 与 Silero VAD,主窗口会显示模型准备页;只有点击「下载并安装」之后,才会从
  固定的公开地址下载这两个模型。已经装过同一套模型的电脑直接复用,不再联网。SenseVoice
  仍是设置里的可选下载;Apple 的语言资源继续由 macOS 管理。
- **导出本场诊断包**:会议详情页「导出会议包」旁边多了「导出本场诊断包」,选好文件夹就
  得到一个 zip,里面只有这一场的脱敏运行记录——模型与 ASR 调用的阶段、状态码、错误分类
  和耗时,录音与会后处理的失败计数——不含转写正文、纪要、说话人姓名、会议标题和音频,
  文件名也不带会议标题;转写或纪要还没生成也照样能导出。设置 → 通用里的全局「导出诊断包」
  另外带一份统一事件账本,以及写明各来源是齐全、缺失还是失败的清单。
- **可以自己选浅色还是深色**:设置 → 通用新增「外观」,三选一「跟随系统 / 浅色 / 深色」,
  默认「跟随系统」,跟着 macOS 的浅色/深色走;选「浅色」或「深色」会立即应用到整个 App,
  并且记住,下次打开还是这一档。

### 改进
- **完整度缺口按「本次录音时长」说明**:某一轨录音短欠时,缺口详情直接写这一轨录到多少秒、
  本次录音一共多少秒、短欠多少秒;互补轨提示形如「system 轨录到 2063s,本次录音共 2064s,
  系统声音内容大概率完整」。不再用容易和日历上会议时段混淆的「会议窗口」说法,判定口径与
  阈值不变;旧会议下次打开 App 时会按新措辞重写一遍。
- **打开会议库、切换会议和导出时窗口不再僵住**:以前这三件事都在界面线程上直接读盘,会议
  攒多了、单场会议长了,窗口就会卡在那儿不响应,也看不出它在忙什么。现在读盘都挪到后台,
  并且把进度显出来:会议库还在读时显示「正在读取会议库…」,某一场的内容还在读时显示
  「正在读取会议内容…」,导出会议包或本场诊断包时显示「正在导出…」并给一个「取消」。
  期间窗口照常能用,排序、选中、页签、滚动、搜索和分组的行为都没变。

### 修复
- **本机没在放声音的会,不再被误判成系统声音采集坏了**:面对面开会、Mac 上没有播放任何
  声音时,「系统播放声音」这一路整场没有数据是正常的。以前 App 会把它当成采集卡住,会中
  弹出「自 mm:ss 起无新数据,即将自动重建采集」的提示并反复自动重建,重建到上限后还留下
  「已停止重试」的横幅。现在从头到尾没出过声的情况保持正常,不提示也不重建;真正「先录到了、
  中途停了」的中断照旧走原来的重建与补静音恢复,麦克风那一路的判定也没变。
- **长转写连续滚动更稳定**:完整转写正文改用原生文档承载,长会议里连续滚动不再让整个
  窗口逐帧重算,滚动位置只在滚动结束后记忆;搜索、复制、说话人筛选、时间戳选段、排除
  与右键操作都保持原样。
- **会议库在深色、大字号和宽窗口下的多处界面问题**:一页纸的「拍板」徽章在深色模式下白字
  配浅底几乎看不清;完整转写的说话人名和时间戳在放大阅读缩放后与正文错位;会中记录的
  「总结留痕」版本选择器默认是个没有标题的空控件,现在显式列出「全部留痕」;一页纸不再钉死
  在固定宽度,宽窗口右侧不再留大片空白;steps / 时间线 / chain 三个横排图在内容超出时
  给出可拖、可点、可用方向键的滚动轨道,末端内容真能走到;完整转写右键菜单固定为业务动作
  +「复制」,不再混进随机器配置变化的系统菜单项。

**怎么看自己在用哪个版本**:设置页右上角显示版本号与 build 号,形如 `v0.9.0 · <build>`。
反馈问题时带上这一串。
